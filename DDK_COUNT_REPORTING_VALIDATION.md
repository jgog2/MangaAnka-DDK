# DDK count and Review Packet cleanup — 2026-10-02

This is a reporting-only pass over the existing DDK pipeline. No MangaAnkā plugin files, title mappings, command grammar, or SQLite schema were changed.

The stored normalization labels already distinguish main chapters, specials, duplicates, provider artifacts, and unresolved rows. `unclassified_records` previously summed artifact labels together with `unclassified` and `provisional`. New audits now store `classified_provider_artifacts`, `provider_artifact_breakdown`, and `unclassified_records` separately. Existing audit JSON with normalization counts is interpreted with the same semantics when shown in the UI or exported; raw acquisition records, logical chapters, mappings, and original JSON evidence are untouched. Older audits without normalization labels cannot be split reliably and require re-audit.

The Audit and Titles tables show artifact and truly unclassified totals. Details shows those totals and a per-class breakdown. The Database footer totals them across latest audited works. Audit summary CSV, Review Packet Markdown/JSON, and Detailed Issues CSV use the same derived counts. Provider artifact findings show `CODE / CODE_REVIEW_REQUIRED` and retain `syntax` or `candidate` confidence; uncertain reference and publication findings keep their existing RESEARCH/UNKNOWN policy. `CODE` denotes the review destination, not a proven software defect.

All-scope Review Packets summarize audited PASS/REVIEW/ERROR counts, number of detailed works, and clean works omitted. Clean PASS titles are listed by title and state only; their chapter rows are not emitted. Explicitly selected clean titles receive the same compact treatment. REVIEW/ERROR titles remain detailed, including those without an unresolved problem row. Status counts use the DDK's current Audit state; a stale `RERUN REQUIRED` audit is counted under REVIEW in the summary.

The focused fixture checks the 390 = 232 canonical + 157 classified artifacts + 1 unclassified case and an Attack-like 142 canonical + 2 classified + 3 unclassified case. It also checks clean omission, packet and CSV counts, class/confidence presentation, and publication-health separation. Automated tests use disposable databases and no live provider requests. The six live titles should be rerun in the future EXE build before relying on current provider-dependent totals for catalog work.
