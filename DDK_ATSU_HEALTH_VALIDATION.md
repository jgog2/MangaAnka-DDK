# Atsu acquisition groups and DDK health consistency

Validated 2026-10-04 against the current local worktrees. The repair is implemented and the primary Qt EXE is rebuilt. No live catalog was opened or changed. No commit, push, tag, release, version bump, schema migration, or command-grammar change was made.

1. **Atsu group model discovered.** `/api/manga/allChapters?mangaId=m7bps` returns acquisition releases, including parallel scanlation groups identified by `scanlationMangaId`. The captured feed contains 481 records: Alpha 248 and Delta 233. Alpha's identifiers are 1–246 plus 32.5 and 40.5; 248 is a record count, not a claimed integer endpoint. Delta is incomplete relative to that primary sequence and also has three additional fractional identifiers. The page API supplies an ordered `scanlators` array. The current client implements Recommended (`auto`) using its first entry, and All exposes parallel releases. Account/source preferences and saved client settings can affect the initial selection; there is no claim that every fresh client always opens Recommended.

   Public sources inspected: [series page](https://atsu.moe/manga/m7bps), [page API](https://atsu.moe/api/manga/page?id=m7bps), [chapter API](https://atsu.moe/api/manga/allChapters?mangaId=m7bps), and its current `index-DaEkcCdv.js` client. Captures are under `C:\MangaAnka DDK\build\atsu-group-evidence`.

2. **Why 19.5 / 89.1 / 92.5 differ between views.** They are Delta acquisitions. Recommended resolves to Alpha in the captured API ordering, so they are absent from that view but present in All. The old connector chose one group only if it covered the entire numeric union. Neither group covered this union, so it returned 481 records. DDK duplicate reconciliation collapsed 230 shared identifiers; the three unmatched decimals then reached the generic fractional classifier. This explains their survival without proving that their content is invalid or special.

3. **Group names.** Alpha and Delta are API-provided `scanlators[].name` values, not local descriptive names. IDs and names are retained independently. No hidden/deleted/status/visibility field was observed in the chapter feed; none is inferred.

4. **General acquisition policy.** The shared Atsu adapter chooses the compatible first API scanlator as the stateless Recommended sequence, after validating parent identity and unique numeric records. Alternate groups do not expand canonical chapters by default. If recommendation metadata is unavailable, the previous deterministic complete-union group fallback remains; otherwise the union is retained conservatively. Single-group inventories remain unchanged. Selection occurs before volume filtering, so filtering cannot silently substitute an alternate group. The Atsu inventory cache contract changes to `atsu-groups-v1`, invalidating old union inventories without changing other providers' cache keys or TTLs.

5. **Retained alternatives.** Original normalized acquisition rows carry a single provenance envelope containing all alternate records, group descriptors, parent identity, and selection basis. Records retain their reader IDs, numbers, explicit titles, page counts, group IDs/names, provider labels, indexes, and creation timestamps. The DDK stores the resolved diagnostics in the existing publication JSON field `provider_group_acquisition`, includes them in review/export contexts, and displays a Scanlation groups section in the existing Details acquisition inspector. Technical details expose individual alternatives. No parallel release is deleted from the evidence.

6. **Unsupported fractional classification.** Alternate-only decimals remain noncanonical acquisition alternatives. They are nonblocking `alternate_fractional` records only when the primary sequence is independently resolved, has a contiguous integer backbone beginning at 0 or 1, and the candidate lies within that sequence with a known preceding primary integer. Conflicting metadata, incompatible groups, incomplete primary evidence, and candidates outside that boundary remain reviewable. No generic decimal rule or special taxonomy was changed.

7. **CODE_REVIEW_REQUIRED.** It is unnecessary for the three Delta-only decimals in the captured, independently resolved Dandadan fixture. It remains necessary for unresolved group candidates. Those are aggregated into `PROVIDER_GROUP_CANDIDATE`, using the existing CODE / CODE_REVIEW_REQUIRED policy. Existing generic fractional findings remain available for other inventories.

8. **Safe alternate recovery.** The shared projection can recover an actual alternate acquisition absent from the primary when trusted, unambiguous explicit reference membership confirms its exact identity, the existing independently established uncompiled evidence confirms it, or two distinct complete compatible other-provider inventories corroborate it. Language and edition must agree; explicit title/volume conflicts fail closed. Multiple alternate candidates must agree. A packaged volume acquisition cannot be promoted as a chapter. The unified-volume plan uses the projection's actual recovered acquisitions so the base plugin can download them. DDK calls the same resolver before normalization; Qt implements no provider policy.

9. **Nine missing reference fractions.** 5.5, 14.5, 23.5, 49.5, 58.5, 67.5, 76.5, 85.5, and 201.5 remain one `CHAPTER_COUNT_DISAGREEMENT`, affecting nine identifiers, classified ACQUISITION / ACQUISITION_ONLY. They do not block publication health. The captured MangaDex evidence does not supply a trusted special taxonomy for these identifiers, so this repair does not relabel them as specials or fabricate provider acquisitions. Existing explicitly recognized special handling is preserved.

10. **Health inconsistency cause.** `ddk_review.review_packet` filtered issues to selected problem IDs and then recomputed whole-audit health from that subset. Selecting only an acquisition disagreement could produce PASS normalization / PARTIAL acquisition; selecting only a fractional problem could produce REVIEW normalization / PASS acquisition for the same audit. The deterministic pre-fix regression reproduced this defect. The original two serialized Audit 19 exports are unavailable, so their exact bytes were not inspected or reconstructed; the code path explains and reproduces the reported pattern.

11. **Authoritative health source.** The existing central `ddk_review.health` evaluator derives audit health at persistence/refresh boundaries using the complete audit's problems and dispositions. Presentation reads that selected audit's persisted `search_audits.health_json`. Review packets now do the same. Problem filtering affects issue detail only. `health_basis: persisted_disposition_adjusted_audit` documents the meaning in review and catalog contexts. Catalog, Details, Problems exports, Copy Diagnostic, Working Set packets, acceptance warnings, history data, and re-audit diffs retain the same semantic source and pin selection.

12. **Raw/effective distinction.** The inspected architecture does not expose two legitimate, separately maintained health tuples. `health_json` is initially calculated from the complete audit and refreshed when valid dispositions alter effective health. Exporting ignored problems does not resurrect their old contribution to health. Audit/database revision and pin still identify the selected snapshot and current disposition state. This repair adds no health evaluator and does not rewrite historical health.
